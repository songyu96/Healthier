# 书本章节知识规格

## 1. 目标

应用在饮食记录、计算器、日评价和周总结之外，提供“与当前应用相关的核心知识”入口。首批内容用于解释现有规则来源和日常行动，不代表两本书的完整整理，不替代原书，也不提供疾病治疗建议。

## 2. 引用定位

仓库内两本 EPUB 均为流式排版：

- 《你是你吃出来的》目录包含 141 个目录项。
- 《你是你吃出来的2：慢病康复的饮食密码》目录包含 226 个多层目录项。
- 两本 EPUB 都没有 page-list 或 page-map；第一册 NCX 还明确记录 totalPageCount=0、maxPageNumber=0。

因此应用统一保存书名、PART、章节标题、EPUB目录第 X/Y 项、约全书 Z% 位置、EPUB 内部文件、可用锚点、原文定位关键词和最近核对日期，并明确注明“纸书页码：该 EPUB 未提供”。开发定位信息默认折叠展示。

不得根据手机屏幕、字号或 HTML 文件编号伪造纸书页码。如果以后获得与当前版本对应的纸书 ISBN 和可靠页码表，可以新增独立的印刷版定位字段。

## 3. 每章内容

知识点数量由章节实际内容决定，不设置固定上下限。每个条目按需包含：

- 本章真正要解决的问题；
- 能改变饮食判断的结论与机制；
- 具体数字、公式、比例和书中案例；
- 容易误解的例外与适用条件；
- 应用如何使用这项知识；
- 关联规则和准确 EPUB 定位。

每条内容必须标注为以下一种来源属性：

- `BOOK_DIRECT`：书中明确结论或机制；
- `BOOK_CASE`：书中数据或案例；
- `APP_DERIVED`：应用为记录、计算或展示作出的推导；
- `SAFETY`：不进入普通健康建议的安全边界。

详情页默认只展示一句话结论、最多四条最优先判断和一个重要边界；机制、其余判断、案例、误用、应用采用方式与完整来源放入展开区。结构化主题也必须保留原始机制知识，不得用判断规则替换或清空。

不为了统一格式生成泛泛的行动建议，也不根据章节标题推测正文内容。每次整理必须重新核对原始 EPUB。

能量、早餐、水果、隐性主食等直接影响记录或计算的章节，试行以下结构：

- 本章最重要的结论；
- 具体怎么计算或判断；
- 书中的关键数字与案例；
- 最容易用错的地方；
- 应用如何处理。

该结构只在确有对应内容时使用。概念性章节继续直接展示真正值得记住的知识，不强行补齐栏目。

公开仓库只保存概括性转述，不复制大段原文。

## 4. 与规则引擎的边界

章节知识是静态说明数据，不参与目标或营养计算。章节知识通过规则编号关联书本规则，计算与评价仍以 domain/rules 为唯一执行入口。

修改摘要不得改变历史目标；修改规则时必须单独升级规则版本并更新测试。

## 5. 覆盖计划

第一阶段收录当前规则规格已经引用的 24 个核心主题，其中第一册 23 个、第二册 1 个。第二册当前仅覆盖安全边界和评价闭环。后续先建立覆盖矩阵，再按 EPUB 原始目录顺序扩展：

1. 第一册其余健康饮食与基础营养章节。
2. 第一册人群与疾病相关章节，仅作知识或安全提示。
3. 第二册各疾病章节，仅作内容摘要和专业就医边界，不接入健康模式自动建议。

每批扩展都应校验编号唯一、目录位置有效、规则关联存在和疾病内容未进入健康模式。
