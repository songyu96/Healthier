# 食物库规则规格（MVP）

版本：`food-library-v2`
适用范围：私人饮食记录、营养摄入估算和书本规则评价。

## 1. 设计边界

食物库只负责提供“摄入事实”，不负责决定目标或输出健康建议。书本规则继续放在 `domain/rules`；食物数据不得反向改变目标。

| 类型 | 含义 | 示例 | MVP 处理 |
| --- | --- | --- | --- |
| `INGREDIENT` | 可直接称重并使用代表性每100克数据的常见单品 | 米饭、白粥、馒头、油条、豆浆 | 加工方式不决定类型；油炸、发酵等另作标签 |
| `COMPOSITE` | 需要分别估算多个主要食材或食物组的食品 | 汉堡、包子、饺子、番茄炒蛋 | 有官方成品数据或透明配方时计算；否则保持未知 |
| `PACKAGED` | 由品牌营养标签描述的包装食品 | 某品牌酸奶、即食燕麦 | 按包装标签录入，品牌或配方变化时更新 |

判断顺序固定为：有明确品牌和包装标签时归入包装食品；否则，若需要分别估算多个主要食材或食物组，归入组合食品；其余归入常见单品。食物类型、食物组和加工标签是三个独立维度。

家常菜通用值保存代表性配料重量和估算成品重量，明确标记为 `RECIPE`。火锅、麻辣烫和烧烤不使用单一固定值，而由用户分别填写畜禽肉、鱼虾、蛋、蔬菜、谷物主食、薯类和豆制品的熟重/可食重量，再生成普通餐食项。锅底、刷油、蘸料和盐统一保持未知；只有用户明确确认油量时才计入数值。

## 2. 数据来源与可信度

来源方法按以下优先顺序记录：

1. 官方食物成分资料（`OFFICIAL_COMPOSITION`），当前内置数据为 USDA SR28、FNDDS 2017–2018、FNDDS 2021–2023，以及中国疾病预防控制中心营养与健康所的中国食物成分表公开查询平台。
2. 食品包装营养标签（`LABEL`）。
3. 明确配方按原料计算（`RECIPE`）。
4. 用户自行录入（`USER`）。

所有可计算数据必须保留来源版本和引用编号。无法确认的数据仍可记录名称、分类和重量，但营养值保持未知，不能用零代替。

USDA SR28 是美国农业部 2015 年发布的 Standard Reference 第 28 版食物成分资料。它可用于近似计算，但品种、产地、烹调和品牌差异仍会造成偏差。

USDA FNDDS（Food and Nutrient Database for Dietary Studies）用于美国膳食调查中已报告食物和饮料的营养计算。本版首批加入 11 个 FNDDS 2017–2018 通用条目，包括组合食品和包装食品；每项保留 FDC ID、英文原条目和版本。FNDDS 通用值不能替代手边产品的包装标签：品牌、配方或规格明确时，应优先新增本地标签数据。

生活场景数据包含 68 个可计算的 FNDDS 2021–2023 条目，覆盖咖啡茶饮、包子、炒饭、面食、快餐、烘焙甜点、聚会酒水、水果、家常蔬菜、粥、豆浆、肉鱼和包装饮料。液体条目的 FNDDS 原值按100克提供，应用以1克≈1毫升作近似并在条目旁明确提示。

新增 4 个 USDA SR Legacy/Foundation 条目：柚子可食部、生小白菜/上海青、生五花肉和生鲜鱿鱼。生活场景库含 24 个透明配方估值：17 个常见单品、组合食品及家常菜配方，以及 7 个供组合餐估算器展开畜禽肉、鱼虾、蛋、蔬菜、谷物主食、薯类和豆制品的代表项。

中国食物成分表已人工核验并收录 37 个条目，其中 29 个五项营养值完整、8 个缺少纤维或个别字段但保留其他已知项。每项直接保存公开查询页 URL；原表能量为 kJ，应用按 `1 kcal = 4.184 kJ` 换算并四舍五入。网页空白和 `Tr` 不会当作 0；日评与周报按能量、蛋白质、脂肪、碳水和纤维分别判断覆盖。该平台声明数据不得未经允许用于商业目的，本项目只为私人非商业使用保留少量必要事实，不批量复制或镜像原表。具体覆盖与排除原因见 `food-coverage-audit.md`。

对于仍无法由名称确定配料、馅料或浓度的食物，应用在注册表内保留 22 个 `REFERENCE` 未知占位，仅用于既有记录、旧备份和内部兼容。它们全部不在普通食物库和餐食选择中展示，也不再作为 HD1 导入确认候选；包装或门店信息明确时应建立本地标签数据，复杂餐食应拆分食材或使用专用估算器。

当前内置注册表共 208 种食物：42 种 SR28 基础数据、11 种 FNDDS 成品和包装食品、37 种中国食物成分表条目，以及 118 种生活场景条目。全库 178 种五项完整、8 种部分营养可计算、22 种保持未知；普通食物库直接展示 186 种可计算条目，排除全部内置未知占位。

`nutritionComplete` 只说明食物与油量是否存在未知项；`nutritionReliability` 另行标记数据可靠性。官方成分和包装标签为高可靠性，普通配方为中等或低可靠性。火锅估算器、普通汉堡、普通炸鸡、肉夹馍等低置信度配方仍可显示当天参考值，但不会进入周报的可靠营养平均或据此触发缺口行动。

## 3. 名称、别名与状态

- 名称必须描述到足以匹配数据的程度，例如“熟鸡胸肉”，不能用“鸡肉”映射所有鸡肉部位。
- 别名仅用于同一种食物、同一加工状态的常见称呼，不用于模糊猜测。
- 生重 `RW`、熟重 `CK`、即食 `EA`、包装标示 `PK` 不自动混算。
- `g` 与 `ml` 不默认等价。只有密度接近且写入 `dataCaveats` 的特例可以近似换算。
- “每枚克数”仅用于稳定、常见的单件食品。

## 4. 分类与食物组

现有分类代码是记录和书本评价之间的最小契约，一个食物条目只有一个主分类。

- 常见单品按真实类别计入结构评价；熟重与书本生重目标不可直接比较时仍标记为不可比。
- 单一组合食品条目在 MVP 中不拆分多个食物组；需要准确结构评价时应使用模板拆成原料记录。
- 组合餐估算器生成多个普通餐食项，因此肉、菜、主食可参与结构检查；其熟重只作营养估算，不伪装成书本生重克数。
- 油盐未知继续显示为可能低估，不自动补数。
- 果汁不得通过别名伪装成鲜果。

饮品使用 `SD` 作为兼容既有 HD1 和备份的主分类代码，界面名称为“饮料（非奶/豆/酒）”。是否含糖是独立属性，不再用“其他”或“高加工食品”代替饮品类别：无糖原味、零糖/代糖、无添加糖但含天然糖、含添加糖和糖状态未知分别记录。牛奶、豆浆和酒精饮品继续使用 `DA`、`SO`、`AL`，避免破坏书本食物组评价；100%果汁及果汁饮料均不计入鲜果目标。

## 5. 用户界面要求

- 默认用中文展示食物类型、分类和数据来源，技术代码放在“术语与来源说明”中。
- 食物库页支持按名称、别名、标签搜索，并按类型、分类筛选。
- 餐食确认页也使用名称输入作为搜索词，可跨分类搜索名称、别名和标签；选择具体食物后自动更新主分类。
- 数据限制紧邻食物展示，例如“牛奶按1克≈1毫升换算”。
- 编辑内置食物只产生本地覆盖，不修改应用静态数据。

## 6. 扩充顺序

1. 当前 208 种内置食物优先覆盖个人高频记录；后续根据实际搜索缺口小批量补充。
2. 加入有可靠公开成分数据的常见组合食品。
3. 在相应食材的生熟状态数据齐备后，再加入可编辑家常菜模板。

扩充前必须验证来源和加工状态；不为追求数量填入未经核验的估算值。

MVP 暂不扩展 `nutrientsPer100` 为配方营养范围，也不增加“一个汉堡”等标准份量范围。当前配方必须展示原料重量并标记可靠性，单件重量不明确时要求用户录入克数。等个人实际记录证明这些功能确有高频需求后，再以小型迁移补充；FNDDS 的自动下载与生成审计也同样暂缓，运行时不会请求外部 API。
