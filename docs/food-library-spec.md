# 食物库规则规格（MVP）

版本：`food-library-v1`  
适用范围：私人饮食记录、营养摄入估算和书本规则评价。

## 1. 设计边界

食物库只负责提供“摄入事实”，不负责决定目标或输出健康建议。书本规则继续放在 `domain/rules`；食物数据不得反向改变目标。

| 类型 | 含义 | 示例 | MVP 处理 |
| --- | --- | --- | --- |
| `INGREDIENT` | 单一基础食材或明确加工状态 | 熟鸡胸肉、米饭、苹果 | 可按可靠的每100克/毫升数据计算 |
| `COMPOSITE` | 多种食材组成、配方会波动的成品 | 汉堡、肉夹馍、饺子 | 有可靠成品数据才计算；只归入一个主分类 |
| `PACKAGED` | 由品牌营养标签描述的包装食品 | 某品牌酸奶、即食燕麦 | 按包装标签录入，品牌或配方变化时更新 |

家常菜模板不是食物。模板应展开为多个基础食材和调味油记录，再进入普通营养计算，以保留真实的蔬菜、蛋白质和主食结构。本版先提供 5 个可编辑的常用搭配模板，不建设复杂菜谱系统。

## 2. 数据来源与可信度

来源方法按以下优先顺序记录：

1. 官方食物成分资料（`OFFICIAL_COMPOSITION`），当前内置数据为 USDA SR28、FNDDS 2017–2018 和 FNDDS 2021–2023。
2. 食品包装营养标签（`LABEL`）。
3. 明确配方按原料计算（`RECIPE`）。
4. 用户自行录入（`USER`）。

所有可计算数据必须保留来源版本和引用编号。无法确认的数据仍可记录名称、分类和重量，但营养值保持未知，不能用零代替。

USDA SR28 是美国农业部 2015 年发布的 Standard Reference 第 28 版食物成分资料。它可用于近似计算，但品种、产地、烹调和品牌差异仍会造成偏差。

USDA FNDDS（Food and Nutrient Database for Dietary Studies）用于美国膳食调查中已报告食物和饮料的营养计算。本版首批加入 11 个 FNDDS 2017–2018 通用条目，包括组合成品和包装食品；每项保留 FDC ID、英文原条目和版本。FNDDS 通用值不能替代手边产品的包装标签：品牌、配方或规格明确时，应优先新增本地标签数据。

生活场景扩充另加入 29 个 FNDDS 2021–2023 条目，覆盖咖啡茶饮、包子、炒饭、面食、快餐、烘焙甜点和聚会酒水。液体条目的 FNDDS 原值按100克提供，应用以1克≈1毫升作近似并在条目旁明确提示。

对于“咖啡”“奶茶”“珍珠奶茶”“包子”“白酒”等仅凭名称无法确定配料、馅料或酒精度的食物，应用提供 `REFERENCE` 记录占位：可以记录类别和摄入量，但营养值保持未知。用户提供门店资料、包装标签或明确品种后，才能改用可计算条目或新增本地数据。

## 3. 名称、别名与状态

- 名称必须描述到足以匹配数据的程度，例如“熟鸡胸肉”，不能用“鸡肉”映射所有鸡肉部位。
- 别名仅用于同一种食物、同一加工状态的常见称呼，不用于模糊猜测。
- 生重 `RW`、熟重 `CK`、即食 `EA`、包装标示 `PK` 不自动混算。
- `g` 与 `ml` 不默认等价。只有密度接近且写入 `dataCaveats` 的特例可以近似换算。
- “每枚克数”仅用于稳定、常见的单件食品。

## 4. 分类与食物组

现有分类代码是记录和书本评价之间的最小契约，一个食物条目只有一个主分类。

- 基础食材按真实类别计入结构评价。
- 组合成品在 MVP 中不拆分多个食物组；需要准确结构评价时应使用模板拆成原料记录。
- 油盐未知继续显示为可能低估，不自动补数。
- 果汁不得通过别名伪装成鲜果。

## 5. 用户界面要求

- 默认用中文展示食物类型、分类和数据来源，技术代码放在“术语与来源说明”中。
- 支持按名称、别名、标签搜索，并按类型、分类筛选。
- 数据限制紧邻食物展示，例如“牛奶按1克≈1毫升换算”。
- 编辑内置食物只产生本地覆盖，不修改应用静态数据。

## 6. 扩充顺序

1. 补足高频基础食材至约120种。
2. 加入有可靠公开成分数据的常见组合成品。
3. 在相应食材的生熟状态数据齐备后，再加入可编辑家常菜模板。

扩充前必须验证来源和加工状态；不为追求数量填入未经核验的估算值。
